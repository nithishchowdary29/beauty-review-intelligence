Week 2

This revised Week 2 report documents the acquisition and assessment of real public data for Beauty Review Intelligence. The business problem remains identifying low rating beauty product feedback from review text for analyst prioritization. The report replaces the earlier synthetic sourcing demonstration with a completed acquisition from Amazon Review Data 2018 All Beauty and its associated product metadata.

The full downloaded review archive contains 371,345 records. A fixed seed uniform reservoir procedure selects 30,000 source rows before label based filtering. The report records the original URLs, archive sizes, source date range, SHA 256 checksums, source schema and sampling method. It compares the chosen collection with the five core sample, Amazon Reviews 2023 and openFDA cosmetic event data, explaining why the alternatives were not combined into the classification target.

The quality assessment includes actual missingness, metadata coverage and duplicate observations. An inspected unmatched example discusses a book, demonstrating why a category name alone is insufficient to establish relevance. The pipeline applies a reproducible metadata coverage filter while acknowledging that it is not a complete semantic taxonomy. The report explains how the retained fields support the existing hypotheses and why the original subcategory comparison is deferred when suitable category labels are unavailable.

Supporting GitHub evidence includes the source manifest, sample profile, cleaning audit and executable Python pipeline. Raw review bodies and reviewer identities are not republished; the code can download the exact public archives privately and verify their checksums. All measured findings refer to the historical public sample, with no claim about current market shares, live customers or operational savings. The document provides a concrete foundation for the following cleaning and modeling stages.

Week 3

This revised Week 3 report presents an executed cleaning and preprocessing pipeline for real public beauty product reviews. It replaces the previous synthetic cleaning counts with measurements from a reproducible 30,000 row sample of Amazon Review Data 2018 All Beauty. The task is to prepare valid review text and rating labels for the same customer feedback classification problem defined in Week 1.

The report explains each transformation in processing order, including rating validation, required product identifiers, metadata title coverage, HTML entity and Unicode normalization, removal of empty bodies, timestamp parsing and exact normalized text deduplication. The actual audit records 441 metadata coverage exclusions, 31 empty body exclusions and 1919 repeated text exclusions, leaving 27,609 analysis records. No artificial faults are inserted and no invalid values are claimed when they were not observed.

A flowchart shows the actual row counts. The duplicate policy retains the earliest source occurrence independently of its label, including ambiguous repeated text groups. Long reviews are preserved and their length is transformed instead of being automatically removed as outliers. The report also documents the implemented word count, punctuation and capitalization features and explains which transformations must be fitted only on training data.

The GitHub repository contains the full pipeline, cleaning audit, structural feature export, partition manifest and independent verification script. Checks establish product separation, exact text separation, valid labels and count reconciliation. Exported evidence excludes review bodies and author identities. The document discusses remaining limitations including shared reviewers, possible near duplicates and incomplete category coverage, so that clean data is not confused with representative data or production readiness.

Week 4

This revised Week 4 report presents actual exploratory analysis and a tested feature engineering comparison using real public beauty reviews. The exploration is limited to the training partition, protecting the final test set from feature selection decisions. The report is part of the consistent Beauty Review Intelligence project and retains the rating one or two versus rating three through five target.

The evidence includes computed rating charts, word count boxplots, product concentration plots and exploratory keyword theme counts. Tables provide sample sizes and proportions alongside the charts. Both target groups have a median length of 24 words in this training sample. An exploratory Mann Whitney statistic and a small rank based effect are discussed with an explicit warning that repeated products and reviewers limit row independent inference. Theme mentions are treated as vocabulary signals rather than verified complaints or causal product defects.

The implemented feature experiment compares TF IDF unigrams and bigrams with the same text representation plus log word count, punctuation density and uppercase share. Scaling and vocabulary fitting occur inside training pipelines. Grouped cross validation and validation metrics are used to assess incremental value. The report preserves the declared average precision selection rule rather than changing metrics to favor additional features.

Supporting GitHub artifacts include the EDA summary, rating counts, theme table, charts, cross validation results and validation comparison. Subcategory findings are not invented because the inspected metadata lacks a usable taxonomy. The report explains how an analyst could investigate value or packaging comments through manual review and operational records, while clearly separating measured associations from future tests and unmeasured business impact.

Week 5

This revised Week 5 report documents actual predictive model training and comparison on real public Amazon beauty review text. The target is a low rating label derived from one or two stars, and the rating itself is excluded from all model inputs. The report compares logistic regression, multinomial naive Bayes and a logistic model with additional style features, together with majority and all flagged baselines.

The analysis uses product disjoint training, validation and final test partitions. Three fold stratified group cross validation within the training data selects regularization or smoothing settings for each model family. The report includes all eight tested parameter settings and their recorded average precision values. Vocabulary and numerical scaling are refitted inside every training fold, avoiding information leakage from evaluation data.

Model family selection uses validation average precision. A separate validation threshold search uses F1, and both model and threshold are frozen before the final test comparison. The selected model is Logistic text at threshold 0.575. The report explains precision, recall, F1, average precision and ROC AUC, and shows the actual model comparison rather than predicted or fabricated scores.

The GitHub repository provides the executable code, cross validation table, validation scores, threshold grid, held out metrics and saved prediction evidence. The document also explains class imbalance, overfitting, underfitting, uncalibrated scores, the feature ablation result and limitations from shared authors and historical sampling. It does not claim production deployment or generalization to unrated messages without additional independent validation. Every reported experimental quantity can be traced to a stored output file.

Week 6

This revised Week 6 report evaluates the completed real public data experiment and translates the results into business decisions that a nontechnical stakeholder can assess. It completes the Beauty Review Intelligence project while explicitly distinguishing historical rating classification performance from unmeasured customer or financial outcomes.

The selected model achieves test precision of 70.4%, recall of 76.4%, F1 of 0.733 and average precision of 0.787. Its confusion matrix contains 667 true positives, 280 false positives, 206 false negatives and 4250 true negatives. The report explains these as actual queue counts and includes the measured confusion matrix, precision recall curves and comparative model charts. It avoids equating the fraction of reviews flagged with staff hours saved.

Uncertainty is assessed with 500 product cluster bootstrap replicates, keeping the trained model and validation selected threshold fixed. The resulting conditional intervals and their limitations are documented. Error references are exported without copying review bodies or reviewer identities, allowing local recovery from the original public archive. An independent verifier checks the saved prediction metrics and partition controls.

The business recommendations focus on a human reviewed pilot, independent channel labels, capacity based threshold selection, manual confirmation of complaint themes and regular auditing of unflagged comments. The GitHub evidence includes the summary, model metrics, prediction file, error cases, charts and verification result. No live deployment, revenue increase, churn reduction or guaranteed evaluation score is claimed. The report directly addresses the need for concrete executed evidence and concludes with the remaining validation needed before operational use.
